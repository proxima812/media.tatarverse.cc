# Стиль и архитектура кода

Идеи Elegant Objects - как ориентир, не как догма. Если чистая функция проще
класса, писать функцию.

## Зависимости передаются явно

Модуль не тянет конфигурацию сам - он ее получает:

```ts
// так
export default function robotsTxt(options: RobotsTxtOptions): AstroIntegration

// не так
import { config } from "../../main.config";  // внутри интеграции
```

Причина не эстетическая: по сигнатуре видно, от чего модуль зависит, его можно
вызвать с другими данными и проверить без сборки. Агент читает один файл и
понимает поток данных.

Исключение - компоненты `.astro` верхнего уровня (`Layout`, `SEO`): они и есть
точка, где конфигурация превращается в разметку. Им импортировать `main.config`
нормально.

## Никакого глобального mutable state

Модульная переменная, которую кто-то записывает, а кто-то читает, - источник багов.
Здесь это уже стреляло: интеграции писали опции в `let _options` на этапе
`astro:config:setup`, а роут-модуль читал **другой инстанс** этого модуля,
поднятый Vite. Опции молча терялись, API выглядел рабочим.

Правило: состояние живет в замыкании фабрики и никуда не утекает.

## Ответственность

Один модуль - одна причина для изменения.

- `types.ts` - контракт;
- `validate.ts` - проверки;
- `shared/dist.ts` - работа с каталогом сборки;
- каждая интеграция - один артефакт.

Рендер отделен от побочного эффекта: `renderRobotsTxt(options)` - чистая функция,
`emitFile()` - запись. Проверять и переиспользовать можно по отдельности.

`main.config.ts` держать плоским и читаемым. Разрастается - выносить блок
в отдельный тип, а не наращивать вложенность.

## Композиция вместо процедурной простыни

Мелкие именованные функции вместо одной длинной: `isSubmittable`, `sectionOf`,
`hashPage`. Имя функции заменяет комментарий.

## Абстракция - только если снижает сложность

Не делать:

- DI-контейнеров;
- интерфейсов ради одной реализации;
- barrel-файлов `index.ts` для реэкспорта;
- фабрик фабрик;
- слоев «на будущее».

`shared/dist.ts` появился потому, что пять интеграций правда пишут в `dist/`.
Одна интеграция - писала бы у себя.

## Комментарии

Комментировать **почему**, а не **что**. Особенно неочевидные ограничения -
их агент не выведет из кода:

```ts
// Astro грузит injected route отдельным инстансом модуля через Vite:
// состояние из astro:config:setup сюда не доходит.
```

Пересказ кода словами не нужен.
