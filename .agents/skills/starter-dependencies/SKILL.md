# Зависимости

Зависимости не запрещены. Запрещены случайные.

## Чеклист перед `bun add`

1. **Astro умеет сам?** Роутинг, эндпоинты, `astro:assets`, `astro:content`,
   интеграции, `astro/loaders`.
2. **Платформа умеет сам?** `URL`, `fetch`, `crypto`, `Intl`, `structuredClone`,
   CSS `:has()`, `content-visibility`, view transitions.
3. **Это несколько строк своей типизированной утилиты?** Тогда написать их.
   `cn()` - 4 строки поверх clsx + tailwind-merge, отдельный пакет не нужен.
4. **Нужна ли она в рантайме?** Стартер статический. Рантайм-зависимость на клиенте
   стоит килобайтов у каждого посетителя; build-time зависимость - ничего.
5. **Совместима с текущими Astro 7 / Tailwind 4 / TS 6?** Проверить peerDependencies
   **до** установки: `npm view <pkg> peerDependencies`. Несовпадение диапазона -
   не всегда стоп: `bun install` только предупреждает, реальная совместимость
   проверяется сборкой (см. `@dualmark/*` ниже).

Не проходит по 1-3 - не ставить.

## Зафиксировано намеренно

| Пакет | Ограничение | Причина |
|---|---|---|
| `typescript` | 6.x | `@astrojs/check` заявляет peer `^5 \|\| ^6`; на TS 7 `astro check` не работает |
| `tailwind-merge` | 3.x | v3 - под Tailwind v4, v2 была под v3 |
| `astro` | 7.x | Node >= 22.12 |
| `@dualmark/astro`/`@dualmark/core`/`@dualmark/converters` | 0.10.x, все три версии совпадают | `peerDependencies` пакета заявляет `astro ^6.1.10` - предупреждение при `bun install` ожидаемо, в проде на Astro 7 работает (проверено сборкой) |
| `@biomejs/biome` | 2.x | поддержка `.astro` (`html.experimentalFullSupportEnabled`) появилась в 2.3+ |

## Удалено намеренно - не возвращать

| Пакет | Почему |
|---|---|
| `@astrojs/tailwind` | Интеграция для Tailwind v3. Здесь `@tailwindcss/vite` |
| `astro-seo-schema` | Peer `schema-dts ^1`, конфликт с `^2`. JSON-LD пишется инлайном |
| `@astrojs/rss` | RSS-фичи в стартере нет. Появится фича - вернуть вместе с ней |
| `@astrojs/react` | Островов нет. Добавлять только под конкретную задачу |
| `astro-meta-tags` | Дублировал собственный SEO-слой |

Зависимость «на будущее» не держим: она устаревает, тянет транзитивные пакеты
и выглядит как используемая.

## Обновление

```bash
npm outdated                       # что вышло
npm view <pkg> peerDependencies    # с чем совместимо
bun install
bun run verify                     # типы + сборка + SEO
```

Мажорные версии - по одной за раз, с прогоном `verify`.
Лишний пакет проще не поставить, чем потом выяснять, кто его использует.
