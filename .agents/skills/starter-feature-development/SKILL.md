# Разработка фичи стартера

## Железное правило

> `enabled: false` означает, что фичи **нет**: ни маршрута, ни файла в `dist/`,
> ни тега в HTML, ни скрипта, ни зависимости в рантайме.

Половинчатое состояние — баг. Именно оно тут уже было: `features.manifest: false`
прятал `<link rel="manifest">`, но `site.webmanifest` всё равно попадал в сборку.

## Цепочка

```
1. types      src/config/types.ts     — контракт
2. значения   main.config.ts          — дефолт (безопасный: выключено)
3. валидация  src/config/validate.ts  — то, что не ловится типами
4. проводка   astro.config.mjs        — передать конфиг ЯВНО
5. реализация src/integrations/*.ts   — генерация артефакта
   или        src/components/*.astro  — теги в <head>
6. проверка   scripts/validate-seo.mjs — если артефакт влияет на SEO
7. документация README.md             — таблица фич
```

Пропущенный шаг 3 или 6 = фича, которая молча не работает.

## Куда класть флаг

**Данные не нужны** → в `features`, обычный `boolean`:

```ts
features: { manifest: false, ai: false, llms: false }
```

**Нужен ключ/ID** → отдельный discriminated union, чтобы включение без данных
было невозможно на уровне типов:

```ts
export type IndexNowConfig =
  | { readonly enabled: false }
  | { readonly enabled: true; readonly key: IndexNowKey };
```

Так `{ enabled: true }` без `key` не скомпилируется. Это лучше любой runtime-проверки.
Не добавлять `key?: string` рядом с `enabled: boolean` — это возвращает невалидное состояние.

## Проводка в astro.config.mjs

```js
...(features.llms ? [llmsTxt({ ...siteMeta, aiPolicy: features.ai })] : []),
```

Интеграция вообще не подключается, когда флаг выключен. Внутри интеграции
проверок «а включён ли я» быть не должно — она не знает про флаги.

## Взаимные ссылки

Если фича A ссылается на артефакт фичи B, ссылку надо гейтить флагом B.
Иначе получается ссылка на 404 — так `robots.txt` ссылался на несуществующий `ai.txt`:

```ts
if (aiPolicy) lines.push(`AI usage policy: ${new URL("ai.txt", site).href}`);
```

## Обязательная проверка обоих состояний

Одного билда мало. Для каждой затронутой фичи:

```bash
# выключено
bun run build && ls dist            # артефакта нет
grep -r "имя-артефакта" dist        # висячих ссылок нет

# включено
bun run build && cat dist/<артефакт>
bun run check:seo
```

Потом **вернуть `main.config.ts` в стартовое состояние** (всё выключено).
Стартер отдаётся с безопасными дефолтами.

## Дефолты стартера

- аналитика — выключена;
- IndexNow — выключен;
- `manifest` / `ai` / `llms` — выключены;
- в конфиге нет значений предыдущего проекта.
