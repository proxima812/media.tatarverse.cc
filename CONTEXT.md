# CONTEXT

Глоссарий домена media.tatarverse.cc. Один термин - одно значение; если в
выводе агента появляется доменное понятие, оно называется словом отсюда,
а не синонимом.

Правила репозитория - в [`AGENTS.md`](./AGENTS.md), решения - в `docs/adr/`.

## Что это за проект

Каталог проектов, которые ведут татары, башкиры и крымские татары: авторы,
каналы, медиа, языковые платформы, уроки, графика. Статический сайт на Astro,
двуязычный (RU - основной, EN - зеркало), контент хранится в репозитории
файлами, а не в базе.

## Ядро домена

**Карточка** (card) - одна запись каталога, один проект. Файл
`src/data/cards/<id>.md`. Схема - `cards` в `src/content.config.ts`.
Не называть «запись», «пост», «проект в базе». Слово «проект» оставлено
за тем, что карточка описывает, за живой сущностью снаружи.

**Id карточки** - имя файла без расширения. Один и тот же id связывает
русскую карточку, ее EN-перевод и логотип. Id не меняется после публикации.

**Черновик карточки** (draft) - карточка с id вида `draft-<slug>`, собранная
ботом из заявки. Намеренно содержит TODO и невалидные поля, чтобы `check`
и `build` падали, пока человек не доведет ее по `starter-card-review`.
Черновик - не «недоделанная карточка», а отдельное состояние с правилом
«красное до ревью».

**Факты** (facts) - 3-4 коротких утверждения о проекте, обязательное поле.
Не «буллиты», не «преимущества»: это фактические сведения, а не реклама.

**Народ** (people, поле `peoples`) - `tatar`, `bashkir`, `crimean-tatar`.
Массив, потому что проект бывает общим для нескольких народов. Не путать
с языком: карточка на русском о башкирской культуре - это `bashkir`.

## Таксономия

Реестр значений - `src/components/Catalog/taxonomy.ts`. Значения, которых
там нет, не существуют: Zod-схема их отклоняет на сборке.

**Категория** (category) - крупный тип проекта: `channel`, `author`, `media`,
`language`, `lessons`, `graphics`, `community`. Список закрытый, расширяется
только через план (см. `AGENTS.md`, раздел «Планы»). У карточки минимум одна.

**Тег** (tag) - уточнение внутри категории: роль, тема, формат, аудитория.
Список большой, но тоже закрытый. У карточки минимум один.

**Группа тегов** (tag group) - `roles`, `topics`, `formats`,
`language-technologies`, `audiences`, `features`. Существует только для
раскладки фильтра в UI; на карточке группа не хранится и не выбирается.

Категория и тег - разные уровни, а не «крупные и мелкие теги».

## Двуязычность

**Источник истины** - русский файл в `src/data/cards/`. Все, что не зависит
от языка (`url`, `logo`, `tags`, `categories`, `peoples`), живет только там.

**Перевод карточки** - `src/data/cards-en/<id>.md`, только `name`,
`description`, `facts`. Слияние поверх русской записи - `localizeCards`
в `src/components/Catalog/localize.ts`.

**Текстовая страница** (page) - цельный документ: политика, условия,
«О проекте», «Добавить проект». `src/data/markdown/` и `src/data/markdown-en/`.
В отличие от карточек это не перевод поверх записи, а зеркальная коллекция:
у EN-страницы свое переведенное тело целиком. Подмена одного фронтматтера
здесь оставила бы текст русским, поэтому механизм принципиально другой.

**Baseline перевода** - `scripts/cards-i18n-baseline.json`, список карточек
без EN, заведенных до правила «новая карточка сразу с переводом». Список
только сокращается. Добавление id туда ради прохождения `check:i18n` -
обход проверки, а не решение.

## Поступление карточек

**Заявка** (submission) - обращение снаружи с просьбой добавить проект.
Приходит через форму Tally (воркер `workers/tally-intake` -> воркфлоу
`tally-submission.yml` -> GitHub issue с лейблом `card-submission`), через
PR на GitHub или напрямую от автора проекта.

Заявка - это не карточка. Путь такой: заявка -> черновик -> карточка.
Состояния и лейблы этого пути - `docs/agents/triage-labels.md`.

## Границы, которые легко перепутать

- **Карточка и проект**: карточка - запись у нас, проект - то, что она описывает.
- **Категория и тег**: разные уровни таксономии, не разные размеры.
- **Народ и язык**: `peoples` - о ком проект, локаль - на каком языке наш сайт.
- **Заявка и карточка**: заявка живет в issue-трекере, карточка - в `src/data/`.
- **Черновик и карточка**: черновик обязан ломать сборку, карточка обязана ее проходить.
