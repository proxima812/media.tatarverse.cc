# Страница проекта: стилистика и UX

**Дата:** 2026-09-05
**Спека:** решение об адресате - `docs/adr/0001-stranica-proekta-dlya-gostya-iz-poiska.md`

## Зачем

Страница проекта показывает категории и теги, но никуда по ним не пускает:
человек видит «Медиа», хочет посмотреть другие медиа - и не может. Из
каталога на страницу ведут триста ссылок, обратно не ведет ни одной, кроме
скромной текстовой «назад» в ряду кнопок. Гость из поиска, а он здесь
основной, не понимает, куда попал: страница начинается сразу с логотипа.

После правки страница представляет себя сама: путь сверху, кликабельная
таксономия, внятное главное действие и понятно, что за каталогом стоят
живые люди.

## Что меняем

- Изменить: `src/components/Catalog/CardDetail.astro` - крошки, порядок
  блоков (название выше пилюль), пилюли-ссылки, сплошная кнопка с доменом,
  факты без нумерации и с заголовком, дата и «предложить правку» в конце,
  выравнивание влево ниже шапки
- Изменить: `src/components/pages/ProjectPage.astro` - заголовок блока
  «Похожие проекты» влево, ссылка «Все проекты в категории»
- Изменить: `src/components/pages/CategoryPage.astro` - те же крошки
- Изменить: `src/components/Catalog/SaveButton.astro` - подпись у кнопки на
  странице проекта, довести до дела проп `size` (последняя ошибка типов)
- Изменить: `src/i18n/locales/{ru,en}.ts` - ключи `card.facts`, `card.edit`,
  `card.added`, `card.allInCategory`, `card.saved`
- Создать: компонент крошек - его используют две страницы, поэтому он
  отдельный, а не скопированный дважды

Крошки уходят и в JSON-LD (`BreadcrumbList`), чтобы путь был виден в выдаче.

## Чего не трогаем

- URL: адреса страниц проектов и категорий не меняются
- Схему карточки: `pubDate` уже есть, новых полей не заводим
- Народы (`peoples`): остаются текстом. Фильтра по народам в каталоге нет,
  и заводить его ради ссылки - отдельная задача
- Карточку каталога (`CatalogCard.astro`): подпись у «сохранить» появляется
  только на странице проекта, в сетке для нее нет места

## Проверка

- `bun run verify`; ошибок типов должно стать ноль - последняя жила в
  `SaveButton`
- `bun run build`: набор страниц в `dist/` не меняется
- Глазами: `/projects/<id>` и `/en/projects/<id>` - путь сверху, переход по
  категории и по тегу, кнопка на сайт проекта, ссылка на правку ведет в
  файл нужной локали
- Ссылка «предложить правку» на английской странице ведет в `cards-en/`,
  если перевод есть, иначе в русский файл

## Риски

- **Мертвая ссылка на правку.** Адрес собирается из id карточки; если файл
  переименован, ссылка ведет в никуда. Проверять на карточке без перевода.
- **Дубли в индексе.** Теги ведут на `/catalog?tags=`, и если такие адреса
  попадут в sitemap, поиск получит копии каталога. Sitemap строится по
  страницам, параметров не знает - но проверить стоит.
- **Крошки при нескольких категориях** берут первую из фронтматтера. Если
  порядок в карточке случайный, путь будет выглядеть произвольным.
