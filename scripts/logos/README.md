# Логотипы карточек

Скрипт ищет кандидатов на официальном URL из русской карточки без заполненного `logo`.
Поиск через Google/Yandex и обход защиты соцсетей не выполняется.
Корень проекта определяется по расположению скрипта, а не текущему каталогу терминала.

## Установка

Python 3.10+; зависимости инструмента не входят в приложение Astro.

```sh
python3 -m venv .cache/logo-venv
.cache/logo-venv/bin/pip install -r scripts/logos/requirements.txt
```

## Сбор кандидатов

```sh
.cache/logo-venv/bin/python scripts/logos/logos.py scan --limit 10
# Все карточки без logo:
.cache/logo-venv/bin/python scripts/logos/logos.py scan
# Отдельные карточки:
.cache/logo-venv/bin/python scripts/logos/logos.py scan --id project-media --id another-channel
```

Каждый запуск создает отдельную папку `.cache/logo-discovery/<scan-id>/`:

- `report.json`: источники, хеши карточек и изображений, ошибки загрузки.
- `images/`: кандидаты в PNG, максимум 512 x 512 без обрезки.
- `preview.html`: локальная страница выбора. Откройте ее в браузере.

Приоритет: JSON-LD `logo`, HTML-изображения с `logo` в имени/атрибутах, иконки, обложки `og:image`/`twitter:image`, запасной `/favicon.ico`.
Для известных соцсетей общие иконки платформы пропускаются. Остальные изображения могут оказаться брендом платформы или обложкой: проверьте их визуально.

Сканирование не меняет карточки. На карточку проверяется до 12 уникальных URL изображений, каждый запрос ограничен 15 секундами и 8 МБ. При ошибке скрипт продолжает обработку. Отчет сохраняется после каждой карточки.
Поддерживаются PNG, JPEG, WebP, GIF (первый кадр) и ICO, минимум 32 пикселя по каждой стороне. SVG и изображения, требующие выполнения JavaScript или авторизации, остаются для ручного поиска. Декодирование HTML рассчитано на UTF-8.

## Применение

В превью выберите по одному изображению для нужных карточек. По умолчанию все пропускаются.
Нажмите «Скачать выбор», затем передайте скачанный файл:

```sh
.cache/logo-venv/bin/python scripts/logos/logos.py apply \
  --report .cache/logo-discovery/<scan-id>/report.json \
  --selection ~/Downloads/selection.json
```

Применение работает без сети. До записи проверяются все выбранные карточки и хеши кандидатов.
Заполненные `logo` пропускаются, изменившиеся карточки и существующие целевые изображения блокируют применение.
Пути записываются как `../../assets/images/logo/<id>.png`; остальные поля и тело Markdown не сериализуются заново. EN-карточки не меняются.

В папке отчета создается `backup-<timestamp>/` с исходными карточками и `changes.json`.
При обрабатываемой ошибке записи текущая серия откатывается. При аварийном завершении процесса используйте резервные копии: восстановите перечисленные Markdown-файлы и удалите только новые PNG из `changes.json`. Папку `.cache` не очищайте до проверки результата.

После применения просмотрите `git diff` и выполните `bun run check`.
Повторное применение пропускает карточки с уже заполненным `logo`.

## Проверки

```sh
.cache/logo-venv/bin/python -m unittest discover -s scripts/logos -v
```

Тесты используют временные карточки и подмененные сетевые ответы. Реальные карточки не меняются.
